# Integration test matrix

Plan: section 2.9 point 11, section 9 (CI) and Appendix D. This page says how each of the 26 databases of 1.0 (plus DuckDB) is tested, with which image and server versions, which variables the tests read, when it runs in CI and how to run it locally.

The tables between the markers below are generated by `cargo xtask matrix` from `xtask/src/db.rs` (containers) and `xtask/src/matrix.rs` (databases). CI fails when they drift (`cargo xtask matrix --check` in `ci.yml` and `nightly.yml`); `cargo xtask matrix --write` regenerates them.

Columns: **Layer** N native, A ADBC, J JDBC bridge. **PR** runs on every pull request (`ci.yml`). **Nightly job** is the job of `nightly.yml`: `servers` (one runner per container and server version), `cloud`, `dedicated`, `os` (three systems).

## What runs where

| Where | Trigger | What |
|---|---|---|
| `ci.yml` `lint` | every PR, push to `master` | fmt, clippy, cargo-deny, typos, `cargo xtask matrix --check` |
| `ci.yml` `test` | every PR | unit, snapshot and UI tests on Windows, macOS, Linux; SQLite TCK; ADBC SQLite (wheels in the repository) |
| `ci.yml` `tck` | every PR | TCK + driver integration tests on PostgreSQL 18, MySQL 8.4, MariaDB 11.4, DynamoDB Local (service containers); H2, Derby, HyperSQL in the JDBC host (Java 21); SQLite |
| `nightly.yml` `servers` | 01:17 UTC daily, manual | every container of the table at every listed version: `db-up --only <key> --image <key>=<image>`, `tck --only <key>` (TCK + `ferrodb-meta` round trips), `ferrodb-drivers` integration tests for PostgreSQL / MySQL / MariaDB / SSH |
| `nightly.yml` `cloud` | daily, when secrets exist | Redshift, Azure SQL, Snowflake, BigQuery, real DynamoDB |
| `nightly.yml` `dedicated` | daily, when secrets exist | Vertica, Sybase ASE on the dedicated environment |
| `nightly.yml` `os` | daily | full workspace suite on Windows, macOS, Linux with Java 21: embedded JDBC TCK, ADBC SQLite, DuckDB driver tests |
| `nightly.yml` `report` | after the above | table of every TCK report (`target/tck/*.md`) in the run summary |

A manual run of the nightly workflow takes `only` (container keys, comma separated) to run a part of the `servers` job.

## Running locally

Docker runs natively or inside WSL (`wsl -e docker` is used when `docker` is not on PATH). URLs use the WSL address on Windows; `FERRODB_TCK_HOST` overrides the host.

The full set needs far more memory than a laptop has (Oracle, Db2, Exasol, Couchbase and Cassandra take 3–4 GB each). Start one database or one group at a time:

```sh
cargo xtask db-up --only pg,mysql          # containers by key (waits until they accept connections)
cargo xtask tck --only pg,mysql            # their TCK tests + ferrodb-meta round trips
cargo xtask tck --only redis --skip-meta   # TCK only
cargo xtask db-down --only pg,mysql

cargo xtask db-up --group nosql            # native | nosql | jdbc | all
cargo xtask db-up --only pg --image pg=postgres:14   # another server version
cargo xtask env --only pg                  # KEY=value lines for a shell or $GITHUB_ENV
cargo xtask tck --only embedded            # SQLite + H2 / Derby / HyperSQL (no container)
cargo xtask matrix                         # this table
```

`--no-wait` skips the readiness checks of `db-up`. Without `--only` / `--group` the commands act on every container (the phase 8 behaviour).

JDBC databases (embedded or in containers) need Java ≥ 17 and the host jar: `mvn -f java/jdbc-host package`. `FERRODB_TCK_JDBC=1` (set by `xtask` for JDBC targets) lets the tests download the driver jars from Maven Central into `target/ferrodb-drivers-test`.

ADBC cloud drivers: the library from the Apache Arrow ADBC wheel (`adbc-driver-snowflake` / `adbc-driver-bigquery` 1.11.0, PyPI) with `FERRODB_ADBC_SNOWFLAKE` / `FERRODB_ADBC_BIGQUERY` pointing at the extracted `libadbc_driver_*.so` (the driver manager does the same inside the application).

## Cloud accounts and secrets

Each cloud target runs only when its secrets are configured in the repository; otherwise the job prints a notice and passes.

| Target | Secrets | Budget guard |
|---|---|---|
| Amazon Redshift | `FERRODB_TCK_REDSHIFT` (URL `redshift://user:pw@endpoint:5439/dev`); IAM variant with `FERRODB_AWS_ROLE_ARN` | Redshift Serverless, base capacity 8 RPU, usage limit 1 RPU-hour per day, AWS Budgets alert |
| Azure SQL | `FERRODB_TCK_AZURESQL` (URL `sqlserver://user:pw@srv.database.windows.net:1433/db`) | serverless General Purpose, 0.5–1 vCore, auto-pause after 60 min, Azure cost alert |
| Snowflake | `FERRODB_TCK_SNOWFLAKE_ACCOUNT`, `_USER`, `_PASSWORD` or `_PRIVATE_KEY` (PEM, written to a temporary file), `_WAREHOUSE`, `_DATABASE`, `_SCHEMA`, `_ROLE` | X-Small warehouse, auto-suspend 60 s, resource monitor with a monthly credit quota that suspends the warehouse |
| Google BigQuery | `FERRODB_TCK_BIGQUERY_PROJECT`, `_DATASET` (scratch dataset), `_LOCATION`, `_CREDENTIALS` (service-account JSON) | on-demand pricing with a custom daily query quota per project; dataset default table expiration 1 day |
| Amazon DynamoDB | `FERRODB_AWS_ROLE_ARN` (OIDC role, `id-token: write`), `FERRODB_AWS_REGION` | on-demand tables created and dropped by the TCK, AWS Budgets alert |
| Vertica (dedicated) | `FERRODB_TCK_VERTICA` (URL `vertica://dbadmin:pw@host:5433/VMart`) | dedicated environment |
| Sybase ASE (dedicated) | `FERRODB_TCK_SYBASE_DEDICATED` (URL `sybase://user:pw@host:5000/db`) | dedicated environment with a developer license |

Every cloud job has `timeout-minutes: 30`; the runs are short TCK passes (one connection, small tables, a 100k-row series), so the daily cost stays at the minimum billing unit of each service.
